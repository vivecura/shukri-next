Recent fixes

Several things were addressed recently — read this first (most recent at top)

  • Domain canonicalization fixed (May 10). Google was indexing some URLs in both vivecura.com and www.vivecura.com forms, splitting ranking signal. The Vercel hosting config was flipped: vivecura.com (no www) is now the primary domain, and www.vivecura.com permanently redirects (308) to it. Result: Google consolidates the duplicate www-indexed URLs into their apex equivalents over 1–4 weeks.
  • vivecura.de unified to vivecura.com (May 10). Both .de variants now permanently redirect to .com. This eliminates duplicate-content risk between the two TLDs and consolidates all SEO signal at one domain. Email at @vivecura.de keeps working unchanged (DNS MX records are independent of HTTP redirects).
  • The /en and /en/about "Redirect error" was confirmed stale (May 10). A live URL inspection in Search Console confirmed both pages are now healthy and crawlable. The error originated from a brief window on May 3 when a locale file bug crashed the React app on those routes (fixed by commit f35ffa4). Validate Fix and Request Indexing have both been triggered; expect the report to clear within 1–4 weeks.
  • The previously submitted sitemap was misconfigured. The Search Console entry pointed to https://www.vivecura.com/blog — that's an HTML page, not a sitemap file — so Google reported "Sitemap is HTML" and couldn't read any URLs. On top of that, a hosting routing rule was sending every URL (including /sitemap.xml) into the React app, so the actual sitemap file was also being served as HTML. Both were fixed: the routing rule was scoped so static files like sitemap.xml and robots.txt are served directly, the wrong entry was removed, and the correct sitemap (https://vivecura.com/sitemap.xml) was resubmitted. Google now reports status "Success" with 30 discovered URLs.
  • The "Why pages aren't indexed" notices in Search Console are normal — not errors. They flag URL variants of the homepage (the http:// version, the www. version) that correctly redirect or defer to the canonical address https://vivecura.com/. Every secure, professionally configured site shows these notices — they confirm the canonical setup is working, not that something is broken. Detailed explanations of each notice appear further down on this page in the section "About Search Console notices."

ℹ️ About Search Console notices

After submitting the sitemap, Google may email a few notices. The names sound alarming. They aren't.

Not an error

"Page with redirect"

Affects URLs like http://vivecura.com/ and http://www.vivecura.com/ — old URL variants that automatically redirect to the canonical address https://vivecura.com/.

This is industry-standard, correct behavior. Every secure, professionally configured website does this: HTTP redirects to HTTPS, the www variant redirects to the canonical version. Without these redirects, the site would have duplicate URLs in Google's index and lose SEO signal.

Google reports these redirects in Search Console because — by definition — the redirected URLs aren't indexed (the destination is). Reporting it is informational, not a flag. Nothing to fix.

Not an error – actually a confirmation

"Alternate page with proper canonical tag"

Affects https://www.vivecura.com/. Google found the www variant of the homepage, saw that the page correctly declares https://vivecura.com/ as the canonical version, and consolidated all SEO signal there.

This is literally what Google asks websites to do. The notice is the engine acknowledging: "Your canonical setup is working." No action needed.

Resolved

"Sitemap can be read, but has errors / Sitemap is HTML"

Earlier, a routing rule on the hosting server was sending every URL — including /sitemap.xml — to the main app, so Google was receiving HTML when it asked for the sitemap.

The rule has been narrowed so that real files (like sitemap.xml and robots.txt) are served directly. The sitemap was then resubmitted and Google now reports status "Success" with 30 discovered URLs. Fully resolved.

Normal · expect gradual change

"Indexed pages: 3 / Not indexed: 3"

The "3 not indexed" are not missing pages — they are the URL variants described above (the homepage typed three different ways). All defer to the canonical homepage. So the count is "3 real pages indexed + 3 alternate spellings of those pages correctly skipped."

The "3 indexed" number will rise steadily over the coming days and weeks as Google crawls the freshly submitted sitemap. New sites are indexed gradually — not all at once.
