1 Was speichert Supabase eigentlich? What exactly does Supabase store?

Eine einzige Postgres-Datenbank hält alles zusammen: Blog, Patienten, Kontaktanfragen und Datei-Uploads. A single Postgres database holds everything together: blog, patients, contact requests, and file uploads.

blog_posts

Alle Blog-Artikel. Pro Artikel eine DE-Zeile und eine EN-Zeile, verlinkt über translation_of. Enthält Slug, Themen, HTML, Thumbnail. All blog posts. One DE row and one EN row per article, linked via translation_of. Holds slug, topics, HTML, thumbnail.

geschrieben von: MCP-Server (Render) written by: MCP server (Render)

anamnese_submissions

Eingegangene Patientenformulare. Komplette Antworten als JSON, plus E-Mail, Handy, Geburtsdatum, Unterschrift. Incoming patient intake forms. All answers as JSON, plus email, phone, date of birth, signature.

geschrieben von: anon (Formular) written by: anonymous (form)

patient_records

Praxis-interne Patientenakte: Diagnose, Medikation, Termine, Notizen, Behandlungsplan, Rechnungen. Practice-internal patient record: diagnosis, medication, appointments, notes, treatment plan, invoices.

geschrieben von: Admin (eingeloggt) written by: admin (logged in)

contact_requests

Nachrichten aus dem Kontaktformular der Website. Messages from the website's contact form.

geschrieben von: anon (Formular) written by: anonymous (form)

lifesummit_submissions

Anmeldungen / Daten für den LifeSummit-Bereich. Sign-ups / data for the LifeSummit area.

geschrieben von: anon (Formular) written by: anonymous (form)

befunde · Storage

Datei-Bucket für hochgeladene Befunde (Patient) und intern hochgeladene Befunde + Rechnungen (Praxis). File bucket for uploaded documents (patient) and internally uploaded documents + invoices (practice).

Domain und Website sind technisch zwei verschiedene Dinge – die Domain ist die Adresse, Vercel ist das Gebäude. Domain and website are technically two different things — the domain is the address, Vercel is the building.

4 Wer hat Zugriff auf was? Who can access what?

Öffentlich Public

Jeder Besucher kann die Website ansehen, das Anamnese-Formular ausfüllen und das Kontaktformular benutzen. Lesen der Datenbank ist nicht möglich – nur einfügen. Any visitor can view the website, fill out the intake form, and use the contact form. Reading the database is not possible — only inserting.

Praxis (Admin) Practice (admin)

Login über /admin mit Supabase Auth. Sieht alle Anamnesen, Kontaktanfragen und Patientenakten. Kann Blog-Artikel taggen. Login via /admin with Supabase Auth. Sees all intake forms, contact requests, and patient records. Can tag blog posts.

MCP-Server (Render) MCP server (Render)

Hat einen service-role-Schlüssel: darf in blog_posts schreiben, ignoriert dabei die Sicherheitsregeln. Patientendaten fasst er nicht an. Holds a service-role key: can write to blog_posts, bypassing security rules. Does not touch patient data.

Entwickler (Sami) Developer (Sami)

Über GitHub Zugriff auf den Code, über Vercel / Render / Supabase auf die jeweiligen Dashboards. Patientendaten nur sichtbar über das normale Admin-Login. Code access via GitHub, dashboards via Vercel / Render / Supabase. Patient data is visible only through the normal admin login.
